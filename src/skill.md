## Extension: Voiden MCP Client

Provides `mcp-connection` and `mcpoperation` block types for connecting to an MCP (Model Context Protocol) server over HTTP — remote or running locally (e.g. `http://localhost:3000/mcp`) — and running one operation against it. Insert with `/mcp` slash command, or paste a `{"mcpServers": {...}}` JSON config (Claude Desktop / Cursor / VS Code / Windsurf style) to fill in the URL and headers automatically — see "JSON config import" below.

### mcp-connection — MCP Connection Container

`mcp-connection` is a **container** block that wraps `mcpurl` and `mcpoperation` children. It is not wrapped inside a `request` block — it is a standalone top-level block.

```yaml
---
type: mcp-connection
attrs:
  uid: "uid"
content:
  - type: mcpurl
    attrs:
      uid: "uid"
    content: "https://mcp.example.com/mcp"
  - type: mcpoperation
    attrs:
      uid: "uid"
      capabilityType: tool   # tool | resource | prompt
      toolName: create_customer
      resourceUri: ""
      promptName: ""
      args: '{"email": "{{USER_EMAIL}}"}'
---
```

When authored interactively in the app, `mcpoperation` auto-discovers the server's tools/resources/prompts as soon as the URL is filled in and lets you pick one from a dropdown (args auto-filled from its schema) — `list_tools`/`list_resources`/`list_prompts` are what powers that discovery, not something you author directly. When hand-writing a `.void` file yourself, just set `capabilityType` and the matching name/uri directly — the actual wire operation (`call_tool`/`read_resource`/`get_prompt`) is derived from `capabilityType`.

### mcpurl — MCP Server URL

Child of `mcp-connection`. Contains the server's HTTP(S) endpoint URL as inline text content.

```yaml
- type: mcpurl
  attrs:
    uid: "uid"
  content: "{{MCP_SERVER_URL}}"
```

### mcpoperation — MCP Operation

Child of `mcp-connection`. Picks which capability to call and its parameters — one attrs-driven block, not a separate block type per capability.

| capabilityType | Wire operation | Relevant attrs |
|---|---|---|
| `tool` | `call_tool` | `toolName`, `args` (JSON object of tool arguments) |
| `resource` | `read_resource` | `resourceUri` (no arguments — the URI is the whole input) |
| `prompt` | `get_prompt` | `promptName`, `args` (JSON object of prompt arguments) |

```yaml
- type: mcpoperation
  attrs:
    uid: "uid"
    capabilityType: resource
    toolName: ""
    resourceUri: "file:///project/notes.txt"
    promptName: ""
    args: '{}'
```

### Complete MCP Example (Call Tool)

```markdown
---
version: __VOIDEN_APP_VERSION__
generatedBy: Voiden app
note: This file is auto-generated by the Voiden app
generatedAt: 2025-01-15T10:30:00.000Z
---

# Create Customer — MCP

```void
---
type: mcp-connection
attrs:
  uid: "mc1onn34-e5f6-7890-abcd-ef1234567890"

  - type: mcpurl
    attrs:
      uid: "mu1rl234-e5f6-7890-abcd-ef1234567890"
    content: "{{MCP_SERVER_URL}}"
  - type: mcpoperation
    attrs:
      uid: "mo1per34-e5f6-7890-abcd-ef1234567890"
      capabilityType: tool
      toolName: create_customer
      resourceUri: ""
      promptName: ""
      args: |
        {
          "email": "{{USER_EMAIL}}"
        }
---
```

### Query Params / Path Params (optional — reused, not MCP-specific)

A `query-table` block in the same section is appended to the server URL as `?key=value`, and a `path-table` block substitutes `{key}` placeholders in the URL — the same generic handling REST requests get (resolved after env-var substitution, before the request is sent). Rarely needed since Streamable-HTTP servers are usually just `{{MCP_SERVER_URL}}`, but useful if a server expects e.g. an API version or tenant ID on the query string / URL path instead of a header.

### JSON config import

Paste a `{"mcpServers": {...}}` JSON config — the shape used by Claude Desktop, Cursor, VS Code, and Windsurf — anywhere in a `.void` file to fill in an `mcp-connection` block automatically:

```json
{
  "mcpServers": {
    "notion": {
      "url": "https://mcp.notion.com/mcp",
      "headers": { "Authorization": "Bearer {{NOTION_TOKEN}}" }
    }
  }
}
```

- Only the **first** server entry is used, and only if it has a `url` field (Streamable-HTTP). If the doc already has an `mcp-connection` block, its URL (and `headers-table`, if the config included `headers`) are replaced in place; otherwise a new block is inserted.
- A `command`-based entry (stdio / local process, e.g. `{"command": "npx", "args": [...]}`) can't be applied — Phase 1 has no stdio transport — and surfaces a toast instead of being silently ignored.
- Implemented in `src/lib/mcpConfigImport.ts` (parsing) and `src/lib/applyMcpImport.ts` (editor mutation), registered via `context.paste.registerPatternHandler` in `plugin.ts`.

Notes:
- HTTP transport only — the server URL must be reachable over `http://`/`https://`, including `localhost` (a locally running Streamable-HTTP server works today; a stdio/command-spawned local server does not). Streamable HTTP handshake (`initialize`) is handled automatically; no need to author it.
- A `call_tool`/`get_prompt` result whose payload marks itself as an error (`isError: true`) still comes back as a normal successful response — check the response body, not just pass/fail, the same way a GraphQL response with a top-level `errors` array is still a 200.
- `assertions-table` works unmodified against the MCP response body — same as any REST/GraphQL request.
